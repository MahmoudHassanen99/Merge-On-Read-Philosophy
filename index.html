The "Merge-on-Read" Philosophy

Tracking Old vs New values in Apache Iceberg and ClickHouse.

Copy-on-Write (CoW)

Values are updated by rewriting the entire data block. The storage always contains the "Final" state of the data.

Old Value: 100
New Value: 150
REWRITTEN

Merge-on-Read (MoR)

Values are updated by adding a new "version" in a patch. The storage contains both the Old and New values simultaneously.

Base File: 100
Patch File: 150
Reader Output: 150

Tech-Specific Implementation

Apache Iceberg

Uses Equality Deletes to target specific values. If you update Price: 100 to 150, Iceberg writes a delete file for the row with Price: 100 and a new data file for 150.

  • - write.update.mode = 'merge-on-read'

ClickHouse

Uses ReplacingMergeTree. You insert a row with the same key but a higher version/timestamp. The old row exists in an older "Part" until the background merge collapses it.

  • - SELECT * FROM table FINAL
