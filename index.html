CoW vs MoR: Engine Comparison

Both Apache Iceberg and ClickHouse implement both strategies.

Copy-on-Write (CoW)

Rewrites entire files to apply changes. Perfect for static, read-heavy data.

In Apache Iceberg

The default mode. When Spark/Flink updates a row, the entire Parquet file is replaced. This avoids "Read Amplification."

In ClickHouse

Triggered via ALTER TABLE ... UPDATE mutations. Background processes rewrite parts to ensure data is physically updated on disk.

Merge-on-Read (MoR)

Writes incremental patches. Critical for high-velocity streaming data.

In Apache Iceberg

Writes Delete Files (Position or Equality). Query engines merge these at runtime. Ideal for CDC pipelines.

In ClickHouse

The ReplacingMergeTree engine logic. New rows "shadow" old ones; SELECT FINAL performs the merge on-the-fly.
